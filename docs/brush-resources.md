# Brush assets, presets, and engines

A tip/texture is sampled image data. A preset is a set of settings plus references to that data. The Codeboard dab engine executes the settings; it does not execute Photoshop, GIMP, or Krita paint engines.

`importBrushResource(path, options)` and the Buffer variant return decoded resources, preset metadata, mappings, missing dependencies, unsupported behavior, warnings, provenance, and source checksums. A failed or unsupported brush is never substituted with a round tip.

The report checksum identifies the original file bytes. Each resource checksum identifies its decoded source mask dimensions and alpha bytes; its resource ID additionally includes the imported dimensions and resampled alpha bytes, plus the tip/texture role. Equal byte arrays with different shapes, or imports at different resolutions, therefore cannot alias the same resource. Repeated equal resources within one import still deduplicate. This changes resource IDs/checksums generated by new imports; stored brush snapshots retain their existing definitions and rendering.

| Resource | Implemented interpretation | Not implemented |
| --- | --- | --- |
| PNG | Alpha, luminance, or inverse-luminance bitmap mask; explicit source attribution | Color stamp behavior; use the selected stroke color |
| GBR | GIMP v1/v2 grayscale and RGBA masks | Full GIMP painting behavior |
| GIH | Extract individual GBR cells and retain pipe metadata in the report | GIMP rank/selection playback; choose a cell explicitly |
| ABR | Sampled tips in v1/v2 and v6.1/v6.2; raw and PackBits, 8-bit samples | Other versions/depths, computed tips, Photoshop descriptor/pattern dynamics |
| KPP | Read preset XML from PNG metadata; actual embedded/linked resource resolution, checksum checking; map supported spacing/opacity/flow values | Size mapping, Krita engine emulation, unsupported PAT resources and most foreign dynamics |
| BUNDLE | Safe bounded ZIP traversal of brush/pattern/preset resources; dependency lookup | Unsupported member formats remain reported |

A KPP preview is never treated as a tip. A preset with a missing `test2.gbr`, for example, reports that filename rather than sampling its PNG thumbnail. Native engine defaults are only introduced by the explicit `brushFromResource(resource, settings)` call made by the author.

Dependency lookup prefers an exact supplied path. Only when that path is absent does it try a unique basename; multiple basename matches stay unresolved and are reported as ambiguous. A preset with no decoded tip reports that fact even if its XML contains a filename. Numeric values outside supported ranges, including blank opacity/flow values, are reported as unmapped rather than silently coerced or omitted: spacing supports 0.02–4 and opacity/flow support 0–1. Imported resource metadata and mapped preset settings remain separate; a GBR's native spacing report does not override a rejected KPP spacing value. Preset size is not currently mapped; set it explicitly when creating the native brush.

```ts
import { importBrushResource, brushFromResource, brushes, renderBrushSwatch } from 'codeboard-studio';
import { writeFile } from 'node:fs/promises';
const report = await importBrushResource('my-tip.png', {
  origin: { source: 'Original painted tip', author: 'Artist', license: 'CC0-1.0', redistribution: 'allowed' },
  maskMode: 'alpha', maxTipSize: 256,
});
console.log({
  resources: report.resources.map(r => ({ id: r.id, name: r.name, width: r.tip.width, height: r.tip.height })),
  missing: report.missingDependencies, unsupported: report.unsupported, warnings: report.warnings,
});
if (!report.resources[0]) throw new Error('No usable resource');
const preset = brushFromResource(report.resources[0], {
  ...brushes.cleanInk, id: 'brush:my-tip', name: 'My textured ink', spacing: .24, size: 80,
});
await writeFile('swatch.png', await renderBrushSwatch(preset));
```

Current import budget: 64 MB input/expanded archive, 4096 members, tip dimensions at most 512. `maxTipSize` defaults to 128; resizing is reported. Authors should choose the import resolution explicitly. This is an import-time decision, not a storage-time quality reduction. Storage retains every resulting alpha value exactly as a Float64 unless its original value is already an integer byte.

Register a custom preset with `project.production.createBrush(preset)` and save the project. Read it through `production.brush`, duplicate it with `duplicateBrush`, or revise it with `reviseBrush`. Painting stores the actual settings at that moment. Preset changes do not mutate earlier artwork. The container deduplicates identical tips and settings by their content; different brush revisions remain independent.

`customizeBrush(base, changes)` creates an independent in-memory preset value, including bitmap alpha, paper texture, provenance and dynamics. Editing that result does not mutate `base`, and later changes to either input do not mutate the result. Dynamics are merged by parameter; a supplied tip or paper texture replaces that whole definition. Supply a distinct `id` when authoring a separate library preset; customization does not allocate an ID or register it. This copies resource arrays in memory once per customization; saved equal payloads still deduplicate in the project container.

`texture: "none"` disables procedural grain, positional texture jitter and random opacity attenuation. It does not remove detail from an imported bitmap tip or disable `paperTexture`. Rotation jitter is controlled separately.

Bitmap brush size specifies the tip's width in source units; its height follows the bitmap's aspect ratio. Artwork-cache bounds include that aspect ratio, possible rotation, speed-size growth and texture marks, so a tall imported tip is not clipped to a square size estimate. The existing raster allocation budget still applies and rejects oversized bounds explicitly. Paper textures are anchored in source coordinates before element and layer placement: `scale` is the size of one texture pixel in those coordinates, and the texture moves/scales with the artwork. A cache crop must not shift its phase.

A stroke whose samples all occupy the same position produces one stationary stamp using the final sample's pressure, tilt and orientation, just like a single-point stroke. Its taper/reveal position is the midpoint of the stroke. Repeated stationary samples do not accumulate extra paint according to elapsed input time; this engine uses distance-based dab spacing, not a timed airbrush. Nonzero paths retain their authored samples and dynamics.

Bitmap hardness variants reuse a cached, colored base tip. A new pressure-derived hardness applies its falloff to a separate canvas instead of rebuilding the tip's alpha pixels for every dab; the base remains unchanged. The existing 128-entry cache includes both bases and hardness variants, and hardness is not quantized. Regression tests switch between hard, pressure-softened and differently colored translucent strokes, then verify exact repeated renders.

`test/raster-parity.test.ts` covers tall rotated tips, texture alignment against an uncached renderer, and revision of an early paint stroke beneath subsequent erasing/repainting, including undo and save/open. Native retained display lists and flattened cached canvases can differ at antialiased edges; the bounds comparison allows one edge pixel, while the texture test checks the fully covered interior exactly. Standard preview and export both use the cached renderer.

`examples/last-light/brush-resource.ts` authors a non-geometric torn-feather tip through the same public vector API, renders it to PNG, imports it, and uses it on curved variable-pressure strokes and the flagship pavement. It writes a compact import report, an editable source-tip project and a swatch project containing the preset. The original example artwork/tip/audio are available under CC0-1.0; code is MIT.

Additional real-file evaluation used GIMP's upstream Acrylic-01.gih (four cells), Krita's `magic_seven.kpp` (actual missing brush and pattern dependencies), and Krita's test ABR `brushes_by_mar_ka_d338ela.abr` (31 extracted sampled tips). Those external evaluation resources are not distributed; their redistribution status is recorded as unknown. No rights are inferred from being downloadable.

Primary format references: [GIMP GBR](https://developer.gimp.org/core/standards/gbr/), [GIMP GIH](https://developer.gimp.org/core/standards/gih/), [Krita resource loading](https://docs.krita.org/en/user_manual/loading_saving_brushes.html), [Krita preset implementation](https://invent.kde.org/graphics/krita/-/blob/master/libs/image/brushengine/kis_paintop_preset.cpp), [Krita ABR reader](https://invent.kde.org/graphics/krita/-/blob/master/libs/brush/kis_abr_brush_collection.cpp). ## Preset revision ownership

Library presets and painted stroke snapshots are separate values. Read a preset with `project.production.brush(id)`, revise it with `reviseBrush(id, changes)`, then pass the revised definition to a new `rasterStroke`. Existing strokes retain their recorded preset version and bitmap/texture dependencies. Applying a different brush to an existing stroke requires an explicit element edit and raster replay.

`createBrush` and `reviseBrush` validate proposed parameters and bitmap/texture dimensions before changing the library. Invalid definitions can be caught and corrected inside an enclosing transaction; malformed new definitions do not consume an automatic brush ID. Revision numbers increase only on a successful preset change. Field validation uses the document's brush schema, and resource shape checks are shared with artwork validation. This does not emulate unsupported foreign brush behavior.

The preset revision test renders an existing stroke, changes its library preset, and verifies the old render is identical. A new stroke uses the revised size and changes the image. After save/open, both stored versions remain distinct; hiding the new stroke restores the original PNG exactly. It also covers caught malformed revisions, failed creation, and undo/redo of the preset change.
