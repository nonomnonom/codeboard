# Implemented capabilities and boundaries

Transitions occupy the last `durationFrames` of the outgoing panel and do not shorten the next panel or move audio. During that interval the outgoing artwork continues at the current global frame, while the incoming panel is sampled at its first frame (including its camera and drawing exposure). Its animation starts on its own first timeline frame; moving overlapping handles are not implemented. The first transition sample uses `1 / durationFrames` progress and the last uses full progress, so a two-frame dissolve samples 50% then 100%. `wipe-left` reveals from the right edge and moves left; `wipe-right` reveals from the left edge and moves right. This corrects their former reversed directions. A zero-duration transition, a cut, or a final panel without a successor renders normally. Transition type and integer duration are validated before mutation; the duration must fit strictly inside the outgoing panel. Pixel tests cover the two wipe directions, dissolve values, boundary frames, session/direct parity, incoming camera/exposure timing and caught invalid edits.

Drawing exposures use integer global frames: `startFrame >= 0` and `endFrame > startFrame`, with the end exclusive. `null` removes the exposure restriction. `production.setExposure()` validates and owns the proposed interval before changing the layer, so an agent can catch an invalid interval and correct it inside the same transaction. The document schema uses the same rule on import/open, including rejecting reversed or empty intervals that older validation accepted. Tests cover fractional/nonfinite frames, caught failures, independent input ownership, successful correction, undo/redo and clearing an exposure. The reopened flagship's expression and lantern-grip exposure checks also pass with this validation.

Dissolves combine weighted premultiplied color/alpha from both frames, rather than simply placing a partially opaque incoming image over a fully opaque outgoing one. Wipes clear the revealed region before drawing the incoming frame. Consequently a fully completed transition matches the incoming frame even where it is transparent; outgoing pixels no longer linger until the cut. Tests cover opaque color mixing, intermediate alpha and exact incoming RGBA values for all three transition types. This is compositing in the renderer's existing color space, not a linear-light color-management claim.

The public API is exported from `src/index.ts`; its generated declarations and `examples/last-light.ts` are executable usage references. There is one authoritative renderer, based on skia-canvas. Preview PNGs, review sheets, and video frames use it.

Offscreen group/mask/clipping composition accounts for camera magnification. Its resolution rounds the effective per-depth zoom upward to a quarter step, never below 1×, and nested intermediate surfaces share that resolution. Vector paths are redrawn into those surfaces; they no longer inherit a panel-resolution bitmap enlarged by the camera. Mask geometry, sibling alpha and layer opacity stay in the same composition coordinates. Enlarged intermediates above 32 megapixels fail explicitly rather than silently lowering resolution. This uses more render memory than the former low-resolution path; it does not add detail to imported pixel surfaces. Native direct/offscreen antialiasing can still differ. Tests compare thin nested vector contours with direct drawing and the old low-resolution enlargement, verify session parity, zoomed masks/clipping with fractional alpha and different depth values, and the allocation error.

Source authoring is a recipe. The saved project is the editable state. Assets are embedded by bytes, while source paths and provenance remain metadata. Renders and caches are derived and are not persisted as primary artwork. Regenerating the source deliberately replaces its output; editing the saved project does not rewrite its JavaScript recipe.

Each selection transform, opacity change or removal is one atomic revision across its selected elements, with one undo step. Selection captures a copy of the requested IDs and treats duplicates as one target. Missing targets reject the operation before any selected element changes, including when the caller catches that rejection inside a larger transaction. Combine several selection operations in `project.transaction(label, work)` when they should share one undo step.

Use `layer.set({ maskLayerId: null })` to detach a mask; omitting that property leaves it unchanged. Null is an editing instruction, not persisted layer data. `production.removeLayer(id)` rejects a layer/group deletion if a surviving layer still uses a mask inside that subtree, naming the consumer and mask IDs. It also requires descendant layer locks to be released first. These checks run before removal, so a caught error leaves the working transaction unchanged. Successful removal also removes review comments anchored to the deleted layers or their elements, while preserving general panel comments. Undo restores both artwork and its removed review anchors. A group containing both its mask and all consumers can be removed together.

`layer.set(...)` validates all supplied settings before assignment, using field schemas shared with document validation. Opacity must be within 0–1, transforms must contain five finite numeric fields, and blend modes/booleans must match their declared types. Transforms replace the local transform rather than merging partial fields; negative scale remains valid for mirroring. Unknown fields are rejected, preventing accidental ID/type replacement or misspelled settings. At the JavaScript boundary, optional fields set to `undefined` are ignored; only `maskLayerId: null` explicitly clears a setting. Parsed transforms are independently owned.

Assigning a mask also validates the proposed dependency graph before applying any accompanying settings. Missing targets, self-masks and direct/indirect group-mask cycles reject immediately, including inside an enclosing transaction. The setter and document validator share the same graph check; completed subgraphs are visited once per check. A rejected setting leaves the entire layer and panel revision unchanged, allowing correction within the same transaction. Full-project schema and relationship validation still runs at transaction commit.

Local authoring mutations copy each touched panel once per transaction for rollback. Untouched panels remain shared internally. Broad production mutations expand the snapshot to the document; commit still validates the complete project. Undo/redo copies the changed branches instead of cloning the full document. See [storage](storage.md) for transaction ownership and remaining allocation costs.

Authoring inputs are values, not live references into the project. Layer exposure, motion points and replacement keyframe transforms are copied when accepted. An element edit callback receives an independent value; its returned element is copied again so references retained by the callback cannot silently mutate committed artwork or bypass revision tracking. This includes typed pixel buffers. Continue editing through the API after commit. `fromJSON()` also owns its imported pixel data; changes to the input document do not change the opened project.

`clipToBelow` uses the immediately preceding sibling's rendered alpha within the same group. A missing, hidden, zero-opacity or out-of-exposure base leaves the clipped layer invisible; it does not reveal the paint unmasked or search earlier siblings for a replacement base. This corrects the former unmasked fallback when the base disappeared. Pixel tests cover exposure boundaries, hiding/deleting the base and clipping inside an opacity group.

The clipping alpha includes the preceding layer's evaluated opacity, including animated fades. The clipped layer then applies its own opacity and blend mode as a separate compositing operation; this is an alpha-mask operation between siblings, not a Photoshop clipping-group emulation. A fractional-alpha buffer is allocated only when the next sibling actually requests clipping. Tests check the resulting RGB values at the fade's start, midpoint and end.

Explicit `maskLayerId` sources use their own ancestor transforms in panel coordinates, not the consumer's parent transform. Source ancestor exposures and opacity are respected; opacity from ancestors shared with the consumer is applied once by the common group. Visibility can hide a mask source from normal artwork without disabling its mask use. A mask source's enclosing groups contribute placement/opacity/exposure, but their separate masks, sibling clipping and blend operations are not inherited into the referenced mask source. The referenced layer's own mask is evaluated. Camera/depth placement is applied to the masked consumer after this panel-space operation. Cross-group and shared-parent pixel tests cover placement, alpha and exposure boundaries.

Element selection transforms compose an affine placement matrix instead of rewriting source points. Rotation and scaling affect complete glyphs, tip shapes, texture and ink width, while original pen coordinates/time/pressure remain intact. Geometry edits and contour booleans still address source-local coordinates. See [artwork transforms](transforms.md).

Live object search is paginated metadata traversal with no full-project copy. Targeted layer reads clone only the requested layer; source-pixel reads can select a region. See [inspection](inspection.md) for limits, ordering and measured clone cost.

A raster stroke edit invalidates its layer replay; subsequent strokes, erasers, masks and blending are recomposited in order. The renderer does not treat a flattened image as editable geometry. A brush preset change affects new strokes; old strokes retain their own versioned settings and tips.

Pixel surfaces are a separate drawing element in raster layers. Their straight-alpha sRGB RGBA8 buffer is authoritative artwork, while their affine matrix locates that artwork in layer coordinates. Rectangular edits use source-pixel coordinates. Subsequent painting/erasing remains ordered above that surface and is replayed after a pixel revision. Import explicitly converts to RGBA8; original high-bit-depth or wide-gamut source data is not retained by that conversion. See [pixel authoring](pixels.md).

Retiming preserves frame-level decisions rather than storing a document snapshot per frame. A shot can contain multiple panels. Layer exposures switch drawings; camera keyframes change framing independently; layer keyframes move artwork; transitions combine adjacent panels. They are separate operations.

Movie audio retains the authored timeline even when a source ends early. Missing source samples contribute silence; a trim beginning beyond the source produces no sound. Clip placement and fade intervals are still measured from the authored clip, and a fade-out is not automatically moved earlier to match a short source. The final mix is padded/trimmed to the movie duration. The FFmpeg integration test decodes the exported AAC to verify silent and audible intervals, and counts decoded video frames for short-source and beyond-EOF trims. It is a timing/data check, not a listening review or a claim about mix quality.

Camera and layer keyframe additions validate their values before allocating an ID. Updates validate a detached proposed keyframe and reject occupied destination frames before replacing the existing value; the updated key retains its ID. Invalid values or collisions can therefore be caught inside an authoring transaction and corrected without retaining partial edits. Adding at an already occupied frame intentionally replaces that frame's key, whereas moving an existing key onto another key is rejected. Keyframe schemas are shared with full-document validation.

Audio clip additions and updates also validate proposed values and fade overlap before mutation. Invalid trim positions, durations, volume or fade lengths can be caught and corrected inside the same transaction; rejected additions do not consume an automatic clip ID. Updates preserve the clip and asset IDs. Clip field validation and fade rules are shared with full-document validation.

Review comment frames are absolute timeline frames. Reordering panels, inserting a duplicate, or deleting an earlier panel shifts comments in surviving panel intervals with that content, including comments that specify only a frame. Spatial anchors and stable object IDs remain unchanged; comments without a frame are not retimed. Structural edits check audio locks before applying these changes, and undo/redo restores comment timing with the artwork timing. Deleting a panel removes comments explicitly anchored to it and frame-only comments inside its interval (start inclusive, end exclusive). Undo restores those removed comments.

Panel deletion also removes comments anchored only to descendant layer/element IDs, without requiring a redundant panel ID. Selection removal cleans up comments on its removed elements while keeping layer and panel notes. Layer, panel and selection removal share the same identity-based anchor cleanup. Panel deletion requires its own and descendant layer locks to be released before any structural change; this is checked even when the lock belongs to the calling actor. An enclosing transaction can catch that rejection, unlock, retry and commit as one undoable edit.

Duration retiming first computes and checks keyframe collisions, collapsed exposures/reveals, and locked audio cues, then applies the updates together. Catching one of these errors inside an enclosing authoring transaction leaves its timing unchanged so the agent can correct the input and continue. Layer reordering likewise checks the sibling destination before removing its source. Uncaught transaction errors still roll back the enclosing transaction.

Panel insertion, move, duplication and deletion stage their structural reference lists before timeline reflow. Reflow checks locked audio before moving panel starts, layer exposures, stroke reveals or keyframes. A rejected operation restores the reference lists and ID counter even when its error is caught inside a larger transaction. This staging holds small structural arrays; artwork is not cloned a second time for the operation.

Runtime limits protect operations without silently reducing quality: exports reject frame counts above the requested budget, imports report unsupported resources and explicit resizing, and damaged documents fail validation. Exact pixel replay has been checked in the pinned Windows/Skia environment. Cross-platform font and renderer equivalence, large-production scaling, and real-time performance are not claimed.

The flagship is an authored, editable 14-panel/30-second sequence with original sound. Current visual direction is restrained geometric ink illustration; further character acting and painterly refinement remain necessary before claiming the master brief's professional visual standard.

Baseline research distinguishes [Storyboard Pro drawing tools](https://docs.toonboom.com/help/storyboard-pro-25/storyboard/drawing/about-drawing-tool.html), [layers](https://docs.toonboom.com/help/storyboard-pro-25/storyboard/getting-started/layers.html), [panel timing](https://docs.toonboom.com/help/storyboard-pro-25/storyboard/timing/change-panel-duration.html), and [camera keys](https://docs.toonboom.com/help/storyboard-pro-25/storyboard/camera/add-keyframe.html) from Harmony's [textured brushes](https://docs.toonboom.com/help/harmony-25/premium/drawing/create-textured-brush.html) and [pencil textures](https://docs.toonboom.com/help/harmony-25/premium/drawing/about-pencil-line-texture.html). These are capability references, not an assertion that the two applications or this engine are interchangeable.

Camera composition bounds include both the base panel and the inverse camera viewport for every root-layer depth, including rotated corners. All sibling intermediates share that panel-space extent, so a camera pan can reveal artwork outside the original frame without losing group contents or their mask/clip relationships. Nested groups inherit the same origin; explicit masks reconstruct ancestor transforms relative to it. Bounds are rounded outward to whole drawing units. This conservative union may allocate unused space for very distant pans or widely separated depth planes; the same 32-megapixel limit rejects excessive allocations. It is not a tiled renderer or an unlimited off-frame canvas. Regression tests place artwork wholly beyond the panel and inspect camera-centered pixels through nested groups, masks and clipping at fractional opacity with simultaneous pan, rotation and zoom.
